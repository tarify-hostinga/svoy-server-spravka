Browser Use в Docker на своём сервере: коротко и с данными

Конспект страницы: 6 разделов коротко, данные на 14 октября 2026 и ответы на 3 вопроса. Полный разбор с примерами: Browser Use в Docker на своём сервере.

Коротко

Browser Use в Docker это ваш агент на Python и браузер Chromium в одном контейнере: в репозитории проекта лежит Dockerfile на python:3.12-slim, где Chromium ставится из системных пакетов. На сервере браузер работает без окна, а модель, которая решает, куда нажать, отвечает по API. Под один агент с браузером берите 2 ядра и 4 ГБ памяти, на каждый параллельный браузер добавляйте ещё.

Конспект по разделам

Что делает Browser Use и зачем ему сервер

Browser Use это библиотека на Python под лицензией MIT, через которую языковая модель управляет браузером: открывает страницы, нажимает кнопки, заполняет формы и вытаскивает данные. Вы пишете задачу текстом, агент сам решает, какие действия выполнить. Разработчики продают и облачную версию с браузерами, но открытую библиотеку можно целиком держать у себя.

Сборка Docker-образа Browser Use

Точка входа образа по умолчанию это утилита browser-use, поэтому для своего скрипта её заменяют флагом --entrypoint. Образ объявляет порты 9242 и 9222; второй это протокол отладки Chrome (CDP), через который браузером можно управлять полностью. Публиковать его в интернет нельзя.

  • Склонируйте репозиторий browser-use/browser-use: Dockerfile в корне ставит Python-зависимости и системный Chromium.
  • Соберите образ командой docker build -t browser-use.
  • Положите свой скрипт с агентом в образ или смонтируйте его томом, ключи передайте через --env-file.

Сколько памяти нужно Browser Use с Chromium

Сама библиотека лёгкая, основную память занимает браузер. Параметр headless по умолчанию определяется автоматически: на сервере без дисплея Chromium запускается без окна. Песочница Chromium ( chromium_sandbox ) включена везде, кроме Docker.

Какие модели подходят для Browser Use

Агенту приходится понимать страницу и планировать несколько шагов вперёд, поэтому небольшой модели сложнее удержать план из нескольких шагов. Начинайте с сильной модели по API, а локальную пробуйте на простых сценариях.

  • OpenAI-совместимый API.
  • Ollama.

Browser Use как MCP-сервер и защита агента

Browser Use умеет работать как локальный MCP-сервер через stdio: команда uvx --from 'browser-use[cli]' browser-use --mcp. Так браузером пользуются Claude Desktop, Cursor и другие MCP-клиенты на той же машине. Чтобы дать к нему доступ по сети, нужен HTTP-транспорт с авторизацией, об этом страница установка MCP-сервера.

  • Задайте allowed_domains: агент не уйдёт со списка сайтов, даже если страница попросит его об этом.
  • Пароли и личные данные передавайте механизмом для чувствительных данных, чтобы они не уходили в текст для модели.
  • Используйте отдельный профиль браузера и отдельные учётные записи для агента.

Вопросы и ответы

Почему Browser Use в Docker не запускает Chromium?

Проверьте, есть ли в образе системные библиотеки браузера. Проще всего собрать образ из Dockerfile репозитория: там Chromium ставится из пакетов Debian, а песочница в контейнере по умолчанию выключена.

Можно ли подключить Browser Use к Claude Desktop или Cursor?

Да, через локальный MCP-сервер: в настройках клиента указывается команда uvx --from browser-use[cli] browser-use --mcp. Ключ модели для агента нужен свой.

Чем Browser Use отличается от Playwright?

В Playwright вы сами пишете шаги и селекторы, Browser Use решает их с помощью модели по тексту задачи. Первый быстрее и дешевле, второй справляется с незнакомыми страницами.
