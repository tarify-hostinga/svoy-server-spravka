Хостинг Supabase на своём сервере: коротко и с данными

Коротко

Главная / Разработка / Supabase Хостинг Supabase на своём сервере это набор контейнеров из репозитория проекта: PostgreSQL, авторизация, REST API, хранилище файлов, Realtime и панель Studio за одним шлюзом на порту 8000. Документация называет минимумом 2 ядра, 4 ГБ памяти и 40 ГБ диска. Supabase заменяет Firebase там, где нужна настоящая реляционная база.

Конспект по разделам

Что заменяет Supabase на своём сервере и из чего он состоит

Supabase это бэкенд, который собирают из готовых частей вокруг PostgreSQL. Вместо того чтобы писать API, вход по почте и загрузку файлов, вы описываете таблицы, а остальное получаете готовым. Он заменяет Firebase и похожие облачные сервисы, с отличием: данные лежат в обычном SQL.

Сколько памяти и диска нужно Supabase

Цифры взяты из документации Supabase для запуска всех компонентов. Нижней границе соответствует MSK Ultra 50 в Таймвеб Клауд (2 vCPU, 4 ГБ, 50 ГБ NVMe) за 5 480 ₽ в месяц на 14 октября 2026. Разделы Realtime, Storage, imgproxy и Edge Runtime можно убрать из compose-файла, если они не нужны, тогда требования падают.

Установка Supabase через Docker Compose

Конфигурация лежит в каталоге docker репозитория Supabase. Ставьте на сервер с Docker Engine и Docker Compose, Git тоже понадобится. Тег в примере взят из документации на 15 октября 2026, свежий смотрите на странице тегов репозитория.

  • Скопируйте конфигурацию с закреплённым тегом выпуска: проект публикует проверенные наборы образов примерно раз в месяц.
  • Создайте.env из примера и выполните скрипт utils/generate-keys.sh: он генерирует пароль базы и ключи.
  • Задайте пароль Studio в DASHBOARD_PASSWORD: панель закрыта обычной HTTP-авторизацией.
  • Укажите адреса в SUPABASE_PUBLIC_URL, API_EXTERNAL_URL и SITE_URL.

Домен и HTTPS для Supabase: прокси перед шлюзом

По умолчанию Supabase отвечает по HTTP. Для рабочего проекта, особенно с входом через внешние сервисы, нужен HTTPS, и документация рекомендует поставить перед шлюзом обратный прокси, то есть программу, которая принимает запросы по HTTPS и передаёт их дальше. Подойдёт Caddy с автоматическими сертификатами.

Supabase или Appwrite для своего сервера

Appwrite решает ту же задачу: готовый бэкенд с авторизацией, базой, хранилищем файлов и функциями. Он тоже запускается набором контейнеров через Docker Compose. Разница в подходе: Supabase строится вокруг PostgreSQL и SQL, у Appwrite свои SDK и модель прав доступа.

  • Supabase выбирают, если команда знает SQL, нужны расширения PostgreSQL вроде pgvector и прямое подключение к базе.
  • Appwrite удобен, когда нужны готовые SDK под много платформ и не хочется писать SQL.

Обновление и копии Supabase

Обновляют установку скриптом update.sh: он подтягивает свежий набор настроек и сливает его с вашими файлами. Перед обновлением прочитайте список изменений в репозитории, там отмечены несовместимые правки. Менять версии отдельных сервисов по одному можно, но совместимость в этом случае не гарантируется.

Вопросы и ответы

Можно ли запустить Supabase на VPS с 2 ГБ памяти?

Документация называет минимумом 4 ГБ для всех компонентов. На 2 ГБ можно запускать урезанный набор без Realtime, Storage и функций, но для рабочего проекта это тесно.

Как установить Supabase в Docker и где взять ключи?

Скопируйте каталог docker из репозитория Supabase, создайте.env из примера и выполните utils/generate-keys.sh: он сгенерирует пароль базы и ключи. Запустите sh run.sh start.

Чем Supabase на своём сервере отличается от облачного Supabase?

Вы сами отвечаете за обновления, копии, HTTPS и ресурсы сервера. Данные и ключи остаются у вас, а часть возможностей облачной платформы может отсутствовать.

Есть ли Supabase в маркетплейсе Таймвеб Клауд?

Да, на 14 октября 2026 у него 540 установок. Маркетплейс создаёт сервер с уже запущенным Supabase, вручную ставить Docker не нужно.
