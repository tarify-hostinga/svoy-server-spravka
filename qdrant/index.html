Установка Qdrant на свой сервер: коротко и с данными

Конспект страницы: 6 разделов коротко, данные на 14 октября 2026 и ответы на 3 вопроса. Полный разбор с примерами: Установка Qdrant на свой сервер.

Коротко

Установка Qdrant занимает одну команду docker run с образом qdrant/qdrant и томом для папки /qdrant/storage. Векторная база данных Qdrant отвечает по HTTP на порту 6333 и по gRPC на 6334, а из коробки работает без пароля, поэтому ключ API и закрытый порт настраивают сразу. Для базы знаний до 100 тыс. фрагментов хватит VPS на 1-2 ядра и 2 ГБ.

Конспект по разделам

Векторная база данных Qdrant: что это и что ей нужно

Qdrant хранит векторы, то есть эмбеддинги текстов и картинок, и быстро находит ближайшие к запросу. Его используют в RAG, поиске по смыслу и рекомендациях. Распространяется под Apache 2.0, официальные клиенты есть для Python, JavaScript, Go, Rust, Java и.NET.

Установка Qdrant в Docker и docker compose

Минимальный запуск из документации с томом для данных: Откройте http://localhost:6333 с самого сервера: Qdrant ответит приветственным сообщением. Тот же запуск в compose, сразу с ключом: Привязка портов к 127.0.0.1 оставляет базу видимой только приложениям на этом сервере. Если приложение живёт в соседнем контейнере того же compose, оно обращается к http://qdrant:6333 и порты можно не публиковать вовсе.

Как закрыть Qdrant ключом API

В README прямо сказано: команда запуска по умолчанию поднимает базу без аутентификации и на всех сетевых интерфейсах. В конфигурации есть два ключа: api_key для чтения и записи и read_only_api_key только для поиска. Клиент передаёт ключ в заголовке api-key.

Сколько памяти и диска нужно Qdrant

Готовых цифр документация не даёт: размер зависит от числа векторов, их размерности и реплик. Посчитать сырой объём просто: векторы × размерность × 4 байта. Миллион векторов размерности 1024 это около 4,1 ГБ, индекс и данные payload добавят сверху.

Снимки, обновление и резервная копия Qdrant

У Qdrant есть снимки (snapshots): копия коллекции в папке snapshots или в S3, GCS и Azure, как задано в конфигурации. Снимок восстанавливается на другом сервере, поэтому копии храните отдельно от базы, схема в разделе бэкапы. Обновление в Docker: docker pull qdrant/qdrant, удалить контейнер и запустить его заново с тем же томом.

Вопросы и ответы

Как задать ключ API для Qdrant в docker compose?

Через переменную окружения QDRANT__SERVICE__API_KEY в сервисе qdrant. После перезапуска запросы без заголовка api-key получат отказ.

Где Qdrant в Docker хранит данные?

В папке /qdrant/storage внутри контейнера. Смонтируйте её томом или папкой хоста, иначе данные пропадут вместе с контейнером.

Можно ли хранить данные Qdrant в S3 или на NFS?

Нет, документация такие хранилища не поддерживает: нужен локальный SSD или NVMe. В S3 можно отправлять только снимки для резервной копии.
