Как работает RAG: шесть шагов от документа до ответа

RAG (retrieval-augmented generation, генерация с поиском) даёт модели ваши документы прямо в запросе. Модель не переучивают: перед ответом система находит подходящие куски текста и подкладывает их в подсказку.

  • Собрать документы: PDF, страницы базы знаний, выгрузки из CRM.
  • Разбить на фрагменты по несколько абзацев, с небольшим перекрытием, чтобы мысль не обрывалась на границе.
  • Посчитать эмбеддинги: модель превращает каждый фрагмент в вектор, набор чисел, похожий у близких по смыслу текстов.
  • Сложить векторы в базу вместе с текстом и ссылкой на источник.

RAG на своём сервере в Docker: минимальный набор

Для своей связки нужны три компонента: модель эмбеддингов, векторная база и языковая модель. Всё запускается в Docker на одном сервере: Модель эмбеддингов скачивают в Ollama так же, как обычную: например docker compose exec ollama ollama pull qwen3-embedding или embeddinggemma. Код загрузки режет документы, получает векторы от Ollama и пишет их в Qdrant.

Сколько места и памяти нужно RAG

Объём векторов считается арифметикой: число фрагментов умножить на размерность и на 4 байта (одно число float32). 100 тыс. фрагментов при размерности 1024 дают около 410 МБ чистых векторов, индекс и служебные данные добавят сверху. Для базы знаний компании это немного: обычный VPS справится с хранением.

Вопросы и ответы

Можно ли сделать RAG полностью без интернета?

Да: модель эмбеддингов и языковая модель в Ollama, векторная база Qdrant, pgvector или Chroma на том же сервере. Для быстрых ответов понадобится видеокарта под языковую модель.

Какая векторная база нужна для RAG?

Для старта подойдёт любая. Qdrant удобен как отдельный сервис, pgvector если уже есть PostgreSQL, Chroma для прототипа на Python. Разница проявляется на миллионах векторов.

Чем RAG отличается от дообучения модели?

RAG подставляет документы в каждый запрос, и обновить знания можно, просто заменив файл. Дообучение меняет веса модели, стоит дороже и не даёт ссылок на источник.
