Коротко

Главная / Разработка / Python-хостинг Хостинг с поддержкой Python бывает трёх видов: платформа деплоя из Git с Docker, виртуальный сервер (VPS) с правами root и обычный виртуальный хостинг с готовой панелью. Веб-приложению на Django, Flask или FastAPI и боту, который работает без остановки, подходят первые два вида, а у третьего обычно упираются в запрет на свои процессы и системные пакеты. Веб-приложение на Python проще всего отдать платформе деплоя с Docker, а процессы с очередями, cron и ботов держать на VPS.

Конспект по разделам

Какие бывают хостинги с поддержкой Python

Слова «поддержка Python» на странице тарифа могут значить разное: от выбора версии интерпретатора в панели до полного доступа к системе. Сравнение по тому, что реально нужно приложению. Для живого проекта выбирают второй или третий вариант.

WSGI и ASGI: что нужно от хостинга для Python

Python-приложение не слушает интернет само. Его запускает прикладной сервер, то есть программа, которая принимает запросы и вызывает ваш код. Тип сервера зависит от фреймворка.

  • WSGI: классический интерфейс для Django и Flask.
  • ASGI: асинхронный интерфейс для FastAPI, Starlette и Django с async-представлениями.

Как выложить Python-приложение на App Platform через Docker

Для Python на платформе деплоя нужен Dockerfile в корне репозитория: готовых пресетов у платформы для этого стека нет, он идёт через Docker. Пример для Flask-приложения в файле app.py: Приложение слушает адрес 0.0.0.0, а не 127.0.0.1: иначе платформа до него не достучится. Данные, записанные внутрь контейнера, пропадают при его пересоздании, поэтому базу берите управляемую ( PostgreSQL от 790 ₽ в месяц), а файлы кладите в S3.

  • Добавьте gunicorn в requirements.txt и проверьте сборку локально командой docker build.
  • Подключите репозиторий GitHub, GitLab, Bitbucket или любой git по адресу.
  • Укажите порт 8000 и переменные окружения: пароли и ключи в образ не кладут.
  • Привяжите домен: SSL платформа выпускает и продлевает сама.

Python-приложение на VPS: gunicorn, systemd и Nginx

На VPS приложение живёт в виртуальном окружении, а за его запуск и перезапуск отвечает systemd. Файл /etc/systemd/system/app.service: Включите службу командой systemctl enable --now app. Число воркеров в документации gunicorn советуют начинать с формулы «ядра × 2 + 1», но для небольшого сервера хватает двух-трёх: у каждого воркера своя копия приложения в памяти.

Бесплатный хостинг с поддержкой Python и его пределы

Бесплатные тарифы нужны для учёбы и первого запуска. Условия у них разные, поэтому перед выбором прочитайте три пункта: останавливается ли приложение при простое, сколько памяти и процессорного времени в месяц дают и можно ли подключить свой домен. Боту и приложению с вебхуками остановка при простое мешает: запрос приходит, когда процесс спит, и первый ответ задерживается.

Вопросы и ответы

Какой хостинг с поддержкой Python выбрать для Django или Flask?

Если администрировать сервер не хочется, платформу деплоя из Git с Dockerfile. Если нужны Celery, Redis и cron, VPS с gunicorn под systemd.

Есть ли бесплатный хостинг с поддержкой Python для постоянной работы?

Бесплатные тарифы чаще рассчитаны на тесты: приложение может засыпать при простое, а память и время работы ограничены. Условия смотрите в описании тарифа.

Нужен ли Docker, чтобы разместить Python-приложение на сервере?

Нет. На VPS хватит виртуального окружения и службы systemd. Docker нужен платформе деплоя и упрощает переезд между серверами.

Сколько памяти нужно Python-приложению на VPS?

Для старта хватит 1-2 ГБ: небольшому Flask или FastAPI достаточно 1 ГБ, а Django с PostgreSQL на том же сервере лучше дать 2 ГБ. MSK Ultra 30 с 2 ГБ стоит 3 000 ₽ в месяц на 14 октября 2026.
